# Architecture Question Universe

Date: 2026-08-28

All questions involve at least two policy functions. None is a novelty claim. `Institutional evidence` refers to the FY2026 Triangle Ehime 2.0 specification and related official horizontal-deployment schemes unless otherwise stated.

## Q1 — Search support × implementation finance
1. **Question:** When does public supplier search increase the value of implementation finance by changing the set of projects that can use it?
2. **Functions:** supplier recruitment/search + implementation finance.
3. **Institutional evidence:** nationwide recruitment, pre-matching and project contracts are jointly verified.
4. **Loop:** search -> applicant pool -> funded implementation -> observed opportunity -> future search return.
5. **Private behavior:** supplier application.
6. **Composition:** wider supplier pool.
7. **Sequencing:** search precedes finance.
8. **Welfare:** possible mis-targeting versus market expansion.
9. **Closest literature:** hard/soft policy mix, search subsidy.
10. **Fatal reduction:** generic complementary instruments.
11. **Actors:** public programme, suppliers, adopters.
12. **Why bundle:** searched matches need financing to implement.
13. **Why one instrument insufficient:** either discovery or cost relief missing.
14. **Generality:** regional technology-adoption programmes.
15. **Kill:** if interaction is only a positive cross-partial.

## Q2 — Multi-site requirement × implementation finance
1. **Question:** When should public implementation finance be conditional on proving a solution at multiple local adopters rather than at one site?
2. **Functions:** multi-site requirement + implementation finance.
3. **Evidence:** at least two Ehime implementation sites are required; implementation costs are publicly supported.
4. **Loop:** screening burden -> supplier entry/design -> financed validation -> observed transferability -> screening value.
5. **Behavior:** application and design effort.
6. **Composition:** scalable versus bespoke projects.
7. **Sequencing:** eligibility condition precedes finance.
8. **Welfare:** fewer entrants versus more transferable funded projects.
9. **Closest literature:** screening/mechanism design, multi-site validation.
10. **Reduction:** subsidy conditional on costly quality signal.
11. **Actors:** programme, supplier, ≥2 adopters.
12. **Bundle:** finance offsets the costly proof required by screening.
13. **Single instrument:** requirement alone may deter; finance alone need not screen scalability.
14. **Generality:** digital, climate, health and manufacturing implementation.
15. **Kill:** if transferability is an exogenous type perfectly revealed by a standard screening contract.

## Q4 — Scalability-by-Design Architecture
1. **Question:** When can a public programme improve the composition of technology projects by combining multi-site scalability requirements, implementation finance and downstream replication support rather than using any one instrument alone?
2. **Functions:** multi-site requirement + implementation finance + diffusion support.
3. **Evidence:** all three are explicitly verified in the current architecture.
4. **Loop:** requirement/finance -> supplier entry and reusable design -> validated project composition -> downstream replication opportunity -> return to entering/designing for multiple sites.
5. **Behavior:** entry, adaptation/modular design, continued commercialization.
6. **Composition:** bespoke versus scalable solutions.
7. **Sequencing:** screening -> financed implementation -> replication support.
8. **Welfare:** entry loss versus better scalable-project selection and private-market formation.
9. **Literature:** policy mix, screening, lead markets, product design, scaling.
10. **Reduction:** screening contract + subsidy + demand pull.
11. **Actors:** programme, supplier, initial adopters, later adopters.
12. **Bundle:** finance counteracts the entry cost imposed by the scalability screen while replication changes the return to passing it.
13. **Single instrument:** no component simultaneously selects, finances proof and creates replication opportunity.
14. **Generality:** regional technology-deployment programmes internationally.
15. **Kill:** if the three-stage interaction collapses to a separable screening transfer plus exogenous market-size term.

14. **Generality:** public market-making programmes.
