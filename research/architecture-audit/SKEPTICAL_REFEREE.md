# Skeptical Referee — Institutional Architecture Audit

Date: 2026-08-28

The referee's objective is to reject the architecture route before any formal model investment.

## Global attack 1 — “This is merely a descriptive policy mix.”

**Assessment:** `SURVIVES ONLY FOR A1`.

Triangle Ehime clearly contains many instruments, but policy-mix complexity is not novelty. A1 survives because the candidate is not “many instruments are complementary”; it is a specific selection/design sequence in which an eligibility rule changes the project pool on which later instruments operate.

## Global attack 2 — “Hard + soft support complementarity is already known, including in Japanese municipalities.”

**Assessment:** `FATAL FOR GENERIC BUNDLES; NOT YET FATAL FOR A1`.

Okamuro–Nishimura (2026) directly makes generic local hard/soft complementarity unavailable as a contribution. A1 must therefore generate a composition/sequencing result, not a positive interaction coefficient.

## Global attack 3 — “This is just PPI / a lead market.”

**Assessment:** `MAJOR`.

Public procurement and lead-market literatures already cover demand pull, certification, market creation and complementary policy tools. A2 is especially vulnerable. A1 survives only because the programme's explicit multi-site eligibility condition and private/local implementation structure may affect applicant/product composition before downstream demand support is realized.

Immediate next-stage test: replace the programme with a standard government lead buyer. If the candidate propositions remain unchanged, kill A1.

## Global attack 4 — “Multiple implementation sites merely improve external validity.”

**Assessment:** `FATAL IF TRUE`.

Multi-site study design and external-validity literatures already analyze site selection/generalization. A1 cannot rest on information quality. Multiple sites matter only if they alter supplier entry/design and the composition of publicly supported technologies.

## Global attack 5 — “The scalability requirement is just a costly signal/screen.”

**Assessment:** `OPEN FATAL TEST`.

This is the strongest formal attack. If suppliers have an exogenous scalable type and the two-site condition merely screens that type, standard mechanism-design logic likely contains the result. A1 needs a response in which supplier design/scalability is at least partly endogenous, or another non-separable interaction that remains within the architecture rather than adding an unrelated mechanism.

## Global attack 6 — “Implementation finance merely satisfies participation.”

**Assessment:** `OPEN FATAL TEST`.

If finance only transfers enough money to pass the multi-site screen, it is a standard subsidy/participation constraint. A1 survives only if finance changes the composition/design response to the scalability condition in a way with welfare content.

## Global attack 7 — “Downstream replication support is an additive market-size term.”

**Assessment:** `OPEN FATAL TEST`.

If the later subsidy simply adds a constant expected demand benefit, the three-part architecture collapses. A1 must show that later replication support changes the incentive to incur the earlier multi-site/reusable-design cost or changes the type/design of projects entering the programme.

## Global attack 8 — “Design for scale is already standard implementation advice.”

**Assessment:** `WEAKENS FRAMING`.

Implementation/public-health literature explicitly advocates designing pilots with scaling in mind. Therefore the contribution cannot be “pilots should plan for scale.” It must be an economic selection/welfare result about how programme instruments jointly generate or distort scalable projects.

## Global attack 9 — “Government is not essential.”

**Assessment:** `UNRESOLVED`.

A private accelerator or platform could impose multi-client requirements and co-finance implementation. Publicness is not yet proved essential. This is not fatal if the result is a sufficiently general IO/organizational theorem, but a public-policy paper would need a minimal public rationale without reintroducing killed generic externality claims.

## Global attack 10 — “Local government is cosmetic.”

**Assessment:** `NOT FATAL AT THIS STAGE`.

A1 can generalize to national/regional deployment programmes. Local-government specificity should not be manufactured through a local-information parameter. Ehime can remain the motivating institution while the theory concerns public deployment architecture more broadly.

# Candidate-specific verdicts

## A1 Scalability-by-Design

**Referee status:** `SURVIVES TO DEDICATED NOVELTY AUDIT`.

Reason: primary sources verify an unusually sharp architecture—multi-site eligibility, public implementation finance, later packaging/horizontal deployment—and the combination can plausibly have opposing effects on entry and project design. The strongest reduction remains unresolved rather than defeated.

## A2 Reference-Market-to-Private-Market Transition

**Referee status:** `BACKUP / VERY HIGH PRIOR-ART RISK`.

Likely reducible to PPI certification, lead-market demand pull or temporary public market creation. Do not advance unless A1 dies and a new audit is explicitly authorized.

## A3 Multi-Site Field Access → Modular Design

**Referee status:** `BACKUP / HIGH PRIOR-ART RISK`.

Likely reducible to subsidized product design/testbeds. Do not auto-advance.

## A4 Implementation-to-Replicable Offering

**Referee status:** `DO NOT ADVANCE`.

Productization plus demand support appears too close to standard product-design/learning logic.

## A5 Regional Embedding

**Referee status:** `KILL AS CORE`.

Agglomeration/place-based FDI/human-capital theory is too close.

# Referee conclusion

The architecture route survives this pre-Stage-0 audit only in a narrow sense. The institution is unquestionably more than a pilot subsidy, but most of its functions map to known theories. One candidate—A1—deserves a serious novelty kill because its **screening × finance × replication** sequence may make project composition endogenous in a non-additive way.

The correct next step is not a model. It is a proposition-level architecture novelty audit against screening/mechanism design, product design, lead markets/PPI, staged support and multi-site/scalability literatures.
