# Policy Pipeline

Date: 2026-08-28

## Reconstructed pipeline

### Phase 0 — local problem / implementation-field discovery

The programme surveys local needs and identifies implementation candidates in priority sectors. Local implementation sites are not assumed to appear automatically.

### Phase 1 — supplier recruitment and pre-matching

Technology firms are recruited nationally. The operator uses networks and co-creation hubs, answers pre-application questions, lists implementation candidates and supports pre-matching.

### Phase 2 — scalable-project screening

The main FY2026 route requires at least two Ehime implementation sites. Selection evaluates proposals before public implementation support is committed. The official recruitment materials emphasize feasibility, economic effects and expected horizontal deployment.

### Phase 3 — funded real-world implementation

Selected suppliers enter project-specific implementation arrangements. Project management, milestone planning, risk management, expenditure inspection, payments, consultation and problem-solving support are provided.

### Phase 4 — evidence, adaptation and evaluation

Projects report products/services, data, IP, progress, outcomes and future direction. Study groups use implementation data and discuss staged goals.

### Phase 5 — stabilization and packaging

The operator provides local accompaniment for continued use and supports suppliers in building packaged offerings and promotional materials suitable for wider adoption.

### Phase 6 — horizontal diffusion

Separate prefectural schemes subsidize customization, functional modification and introduction of previously validated Triangle Ehime solutions by additional local adopters in multiple sectors.

### Phase 7 — regional embedding / private continuation

Networking supports private finance, local customers and employment. Separate architecture seeks local branch/R&D-site establishment and AI-human-capital formation. Project retention is followed for years after selection.

## Why sequence may matter

The architecture is not simply a list of simultaneous instruments. In the verified FY2026 structure:

`field discovery -> multi-site application/screening -> funded implementation -> data/evaluation -> packaging/accompaniment -> adopter-side horizontal-deployment support -> private continuation/embedding`

The central audit question is whether later stages change ex-ante supplier entry/design and whether earlier stages change the productivity of later diffusion support.

## Counterfactual sequences for later audit

1. implementation subsidy without multi-site/scalability screening;
2. multi-site requirement without public implementation finance;
3. diffusion subsidy without an earlier publicly governed implementation stage;
4. pilot completion without packaging/continued implementation support;
5. local field access without later market-development instruments;
6. direct procurement by government instead of government-sponsored private implementation.

No welfare ranking is asserted at this architecture-audit stage.
